# Fixtures

Captures in the `tools/capture.py` record format, used by the collector's replay
suite (the collector's single test seam) and to seed the panel's end-to-end runs.

Record format: one JSON object per line with `recv_ms` (the collector's clock),
`kind` (`mqtt`, `rest`, `note`, `meta`) and the payload. MQTT records carry the
raw broker payload, unfiltered.

## Files

| File | Provenance | Commit it? |
|---|---|---|
| `raw-*.jsonl` | Unredacted output of `tools/capture.py capture` | **No**, gitignored |
| `job-*.jsonl.gz` | Redacted real capture from a mower | Yes, gzipped |
| `synthetic-job.jsonl.gz` | Generated by `make_synthetic.py` | Yes, with its generator |

Trim long real captures to a representative window before committing. A two-hour
Job is roughly seven thousand points, and the repository should not carry whole
seasons of mowing.

## The synthetic fixture is provisional

`synthetic-job.jsonl.gz` exists so the replay harness can be built before a real
capture arrives. Regenerate it with:

```bash
python fixtures/make_synthetic.py
```

It is a **generator, not a blob**, so every assumption is reviewable as code.
`make_synthetic.py` marks each payload shape as `OBSERVED` (copied from the
real-session fixtures in the SDK's own tests, or from the field observations
catalogued in the SDK data audit) or `INVENTED` (lawn geometry, event ordering,
identifiers, battery curve).

**When a real capture lands, any replay assertion the real data contradicts is a
bug found in the rules, not in the test.** Correct `make_synthetic.py`, note what
changed, and regenerate. The numeric `vehicleState` values are the likeliest to
be wrong: sources disagree on which of 1, 2 and 3 mean docked, charging and idle.

It simulates about five hours containing one Job, and exercises: docked
heartbeats and the all-zero placeholder, dock drift, departure with
`subtotalArea` at zero beside a stale `mowingPercentage` of 100, the zone list,
a zone change resetting `currentMowProgress` while `mowingPercentage` continues,
a charging break that resumes the same Job rather than starting a new one, a
four-minute broker gap while the mower is still running, one point delivered 90
seconds late, the docking arrival pose that reveals the dock location, and the
`mowStartType: 0` "no task" message that must not be read as a new Job.

REST snapshots contain no latitude or longitude key, because the audit found the
public API never returns one. If a real capture disproves that, the Dock origin
decision changes and so must this file.
